# 编排层与 AI 请求层协作约定

日期：2026-09-23。状态：原型阶段的协作草案。对应[编排层原型设计计划](orchestration-layer.md)和 [AI 请求层设计计划](ai-request-layer.md)。

## 分工与交接

| 工作 | 负责人 | 交接产物 |
| --- | --- | --- |
| LangGraph 原型、Context 选择、历史记忆导入、设定卡装配 | 编排侧（本次开发方向） | 图阶段说明、统一请求样本、构造记录和验收样本 |
| `send_messages`、模型配置、协议适配、流式结果和调用错误 | AI 请求侧协作者 | 稳定的请求／响应契约、能力限制和调用样本 |
| 契约冻结与端到端联调 | 双方共同 | 字段及语义清单、异常场景结论、变更记录 |
| 评审产品行为和数据优先级 | 项目维护者 | 冲突处理、隐私和持久化规则的决定 |

当前仓库尚无上述产品实现。原型可用固定样本推进，但对外宣称联调完成之前，必须接入真实的统一请求层。

## 联调前共同确认

| 契约 | 需要说清楚的语义 |
| --- | --- |
| 输入消息 | role、内容块顺序、工具定义及调用 ID；设定卡和记忆渲染后仍使用统一协议 |
| 模型预算 | 上下文窗口、预留输出上限、token 统计来源及未知用量的表示 |
| 完成结果 | 增量与完整消息的关系、结束原因、工具调用与不完整响应的表示 |
| 错误与取消 | 哪些错误可重试、已有输出时的行为、取消后的保存规则 |
| 关联标识 | 会话 ID、本轮 ID、请求 ID、快照版本和 trace ID 的传递位置 |

请求层只处理一次模型调用。工具执行与是否再次调用属于编排层；首版原型不执行工具。若模型返回工具调用，双方先约定显式的“暂不支持”结果，避免误当作普通文本完成。请求层配置由其协作者负责，编排侧只读取必要的预算与能力摘要。

## 变更节奏

1. 双方先用文档和样本确认契约；未决字段标注为候选，不写成现有 API。
2. 各自按职责开发。字段或语义变化先更新协作记录，并同步受影响的样本。
3. 联调先核对单轮文本，再看历史和设定卡装配、异常与观测；发现问题按所属层定位。
4. Rust 迁移决策前复核统一消息和 trace 语义，避免把 LangGraph 专用状态格式当成长期数据格式。

依据 [AGENTS.md](../../AGENTS.md)，Agent 可维护文档、测试和项目辅助脚本；产品功能与核心逻辑由人类贡献者实现。任何提交仅包含本次明确指定的文件，并保留他人的进行中改动。

## 待确认

- 请求层首次支持的协议、返回契约和预算信息如何公开。
- 设定卡与用户更正、历史记忆冲突时的最终优先级。
- 历史记录的来源、导入格式、删除与重导入规则。
- Python 原型与 Rust 核心的交接方式，以及是否需要跨进程运行。
- Langfuse 部署位置、真实内容采样策略和保留期限。
